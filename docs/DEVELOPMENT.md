# Development playbook

Deeper than the README quick-start. This doc is the place to look when something specific breaks or you need to extend the codebase.

> **Audience:** developer who already cloned the repo, ran `pnpm install`, and got a green `pnpm typecheck`. If you're not there yet, start with the [README](../README.md#run-it-locally).

## Workspaces at a glance

```
sdk/      pure TS — encrypt + ika + btc adapters, mock-mode-only today
keeper/   Node 24 daemon — polls Solana for Pending matches, signs BTC, finalizes
app/      Next.js 16.2 frontend — UI + Server Actions for the deposit wizard
programs/ Rust — Anchor program (obsidian_core)
```

The TS workspaces are linked via pnpm, so `@obsidian-desk/sdk` resolves to `sdk/dist/` (built output, not source). **You must `pnpm -F @obsidian-desk/sdk build` once after a clone** — otherwise `keeper` and `app` typechecks fail with `TS2307: Cannot find module '@obsidian-desk/sdk'`. CI does this automatically; locally you only need to do it again when you edit SDK source.

## Per-workspace debug tips

### sdk/

Run a single test file with the native Node 24 strip:

```bash
node --test --experimental-strip-types --no-warnings sdk/tests/ika.test.ts
```

The mock store is process-local. If you need to inspect what's in it from a script:

```ts
import * as ika from './sdk/src/ika.ts';
console.log('mockSize=', ika._mockSize());
const dw = await ika.createDWallet('bitcoin-signet');
console.log(dw, ika._mockAddressOf(dw.id));
```

### keeper/

Run with the standard Node inspector for breakpoint debugging:

```bash
node --inspect-brk=127.0.0.1:9229 --import tsx keeper/src/index.ts
```

Then attach Chrome DevTools (`chrome://inspect`) or VS Code's "Attach to Node Process". The keeper exposes verbose mock-store dbg lines when `KEEPER_DEBUG=1` is set:

```bash
KEEPER_DEBUG=1 ANCHOR_PROVIDER_URL=http://127.0.0.1:18899 \
  pnpm -F @obsidian-desk/keeper dev
```

### app/

Next.js dev server with React DevTools is the default flow:

```bash
pnpm -F @obsidian-desk/app dev
# open http://127.0.0.1:13000
```

For React Server Components + Server Actions, attach a Node inspector to the dev server:

```bash
NODE_OPTIONS='--inspect=127.0.0.1:9230' pnpm -F @obsidian-desk/app dev
```

Browser breakpoints work in DevTools as expected; client/server boundary issues usually show up as a hydration mismatch warning — fix by gating render on a `useEffect` set-state pair (see `app/components/shell/dwallet-chip.tsx` for the pattern).

### programs/obsidian-core/

`anchor build` produces `target/deploy/obsidian_core.so` + `target/idl/obsidian_core.json`. Increase Solana log verbosity:

```bash
RUST_LOG=solana_runtime::message_processor=debug \
  solana-test-validator --rpc-port 18899 --bind-address 127.0.0.1 --reset
```

Then `solana logs --url http://127.0.0.1:18899 H25yY5o4emorZ9qMHAUvJhdtrFjDSeYy2MVYurpQbeLp` will tail the program's `msg!` output.

## Regenerating Anchor IDL types

The TS-side types under `target/types/obsidian_core.ts` are generated by `anchor build`. If you change `programs/obsidian-core/src/` and the keeper or tests start complaining about a missing instruction or account, regenerate:

```bash
anchor build
# target/types/obsidian_core.ts is rewritten in place
# the keeper imports `target/idl/obsidian_core.json` at runtime, also rewritten
```

The frontend doesn't import the IDL types today (it talks to the SDK + zustand stores), so you don't usually need to restart the Next dev server after a rebuild.

## Swapping the Encrypt or Ika SDK to a real backend

When the upstream packages start shipping compiled JS (gap E5 / I0 in [`docs/gaps.md`](gaps.md)):

1. `pnpm -F @obsidian-desk/sdk add @encrypt.xyz/...` (or whatever the published name is).
2. In `sdk/src/encrypt.ts`, locate the `case 'real':` branch (currently throws `VendorSDKUnavailableError`) and call the real client.
3. The adapter's exported types — `Side`, `EncryptedOrderBlob`, `Chain`, `DWallet`, `Policy` — should not change. The whole point of the adapter is that callers (`keeper`, `app`, tests) do NOT have to update.
4. Run `pnpm -F @obsidian-desk/sdk test`. If the byte-shape of real ciphertexts differs from the mock 32-byte tagged blob, update `MOCK_TAG`/`CT_ID_LEN` constants and any fixtures.
5. Run `anchor test` to confirm the whole flow still settles.

## Profiling FHE operations

The mock CPI in `programs/obsidian-core/src/encrypt_cpi.rs` returns deterministic 100-byte placeholders, so its compute-unit cost is uninteresting. Once we swap to real Encrypt CPI in P3+, profile per-instruction cost with:

```bash
solana logs | grep -E "consumed [0-9]+ of [0-9]+"
```

Per-CT size for the current scaffold is `CT_MAX = 3000` bytes (gap E0 — Solana's CPI realloc cap is 10 240 B, divided across the three CT slots in `EncryptedOrder` plus the linked-list overhead).

## Adding a new market

`initialize_market` in `programs/obsidian-core/src/lib.rs` creates a fresh `MarketState` PDA seeded by `(base_mint, quote_mint)`. To add ETH/USDC:

```ts
const baseMint  = ETH_MINT;   // SPL mint pubkey for wrapped ETH on Solana
const quoteMint = USDC_MINT;  // SPL mint pubkey for USDC

const [market] = PublicKey.findProgramAddressSync(
  [Buffer.from('market'), baseMint.toBuffer(), quoteMint.toBuffer()],
  program.programId,
);

await program.methods
  .initializeMarket(baseMint, quoteMint)
  .accountsPartial({
    market,
    settleVault: ...,   // any pubkey for now (P2 scaffold accepts opaque)
    ikaPolicy: ...,
    admin: provider.wallet.publicKey,
  })
  .rpc({ commitment: 'confirmed' });
```

The scaffold currently doesn't price-feed ETH separately — for the demo we use BTC/USDC throughout. Adding a real ETH market would need:

- A Pyth price feed binding for the chart (`app/components/trade/price-chart.tsx` — currently seeds synthetic data centered on $69 850).
- A Bitcoin-equivalent settlement path that's NOT BTC. Today the SDK + keeper assume P2WPKH on signet — wiring an ETH dWallet would need a parallel `sdk/src/eth.ts` adapter and a fork of `keeper/src/poll.ts`.

For the hackathon, stick with BTC/USDC.

## Common iteration pitfalls

| Symptom | Fix |
|---|---|
| `TS2307: Cannot find module '@obsidian-desk/sdk'` | `pnpm -F @obsidian-desk/sdk build` (workspace types come from `dist/`, not source) |
| `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING` | A vendor package shipped uncompiled `.ts` — Node 24 won't strip from `node_modules`. Set `OBSIDIAN_*_MODE=mock` (the default) until the vendor publishes JS |
| Mocha hangs forever on Anchor tests | Anchor's WS event listeners hang against a manually-spawned validator. Use `getTransaction(sig).meta.logMessages` parsing of `Program data:` lines instead — see `tests/obsidian-core.ts` `eventsFor()` helper |
| `Failed to reallocate account data` | A ciphertext `Vec<u8>` exceeded `CT_MAX = 3000`. Solana's CPI realloc cap is 10 240 B for the whole account; the three CT slots + headers + linked-list pointer fight over that budget |
| `Blockhash not found` on `--rpc` ops | Default `processed` commitment returns blockhashes the validator hasn't finalized. Build the provider explicitly with `commitment: 'confirmed', preflightCommitment: 'confirmed'` |
| Hydration mismatch in app/ for a persisted-store-backed component | Render a skeleton on first paint, set state in a `useEffect`, only render the real markup after hydration. Pattern: `app/components/shell/dwallet-chip.tsx` |
| Docker build fails on `usb`/`node-gyp` in alpine | An umbrella package dragged in a hardware-wallet adapter. Switch to per-wallet packages (`@solana/wallet-adapter-phantom` etc.) instead of the meta `@solana/wallet-adapter-wallets` |
